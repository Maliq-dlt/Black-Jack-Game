## 2024-04-16 - Avoid Synchronous LocalStorage Reads in React State Initialization
**Learning:** In `App.tsx`, complex states like `gameState` were being initialized using an object literal inside `useState`, which included calls to `loadMeta()` and `loadSettings()`. These functions perform synchronous `localStorage.getItem` reads. Because `useState(initialValue)` evaluates `initialValue` on every render (even though it's only used on the first render), these synchronous I/O operations were blocking the main thread on every re-render of the main app component. This is a common performance bottleneck in React apps that manage persistence.
**Action:** Always use lazy state initialization (e.g., `useState(() => loadData())`) for states that require complex computation or synchronous I/O during initialization to ensure they only run once on component mount.
