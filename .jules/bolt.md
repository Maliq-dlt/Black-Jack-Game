## 2024-05-24 - React `useState` Re-render Bottleneck with Synchronous LocalStorage Reads
**Learning:** In highly complex React components like `App.tsx` that act as central state hubs and re-render frequently, initializing `useState` directly with the result of a function that performs synchronous `localStorage.getItem` reads (e.g. `const [gameState, setGameState] = useState<GameState>(loadData())`) is a massive performance bottleneck. Even though React ignores the returned value on subsequent renders, the JavaScript engine still evaluates the argument, meaning `localStorage.getItem` is executed on *every* single re-render of the component.
**Action:** Always wrap expensive synchronous initialization logic (like file I/O or `localStorage` reads) inside a lazy state initialization function: `useState(() => loadData())`. This ensures the expensive operation is truly only executed once during the initial mount phase. Additionally, persistence loading functions should be defined outside the component body to prevent them from being unnecessarily recreated on every render.
